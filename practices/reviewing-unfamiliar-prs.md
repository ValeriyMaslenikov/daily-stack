# Reviewing unfamiliar PRs

How I review a PR in a codebase I don't know well.

1. Get the architecture before the diff. Build a map of the repo with
   [Understand-Anything](../ai/understand-anything/) and look at where the
   changed files sit and what depends on them.
2. Ask questions about the touched areas before forming opinions on the change.
3. Then read the diff with that context.

This is still forming — I'll expand it as the habit settles.
